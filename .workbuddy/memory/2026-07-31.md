## V1.2页面显示Bug修复 (17:36)

### 问题描述
用户截图反馈GitHub Pages在线页面显示异常：
1. ❌ 新闻数据未渲染（表格中只有1行，且是页脚信息）
2. ❌ 页脚信息错位（被显示为表格的一行数据）
3. ❌ 统计数据虽然显示正确（38条），但实际内容未展示

### 根本原因分析
**核心问题**: `update-news.sh` 脚本生成HTML时使用了**99处双花括号 `{{ }}`**

影响范围：
- **CSS样式完全崩溃**: 所有CSS规则使用`{{` `}}`导致样式解析失败
- **JavaScript语法错误**: 所有函数体、代码块、对象字面量都使用双花括号
- **模板字符串错误**: `${{...}}` 应该是 `${...}`

**技术根因**: Python f-string或字符串拼接时，花括号被错误地双重转义

### 修复过程

#### 第1步：定位问题
- 检查本地index.html文件
- 发现第8行开始所有CSS都使用双花括号
- JavaScript部分（360-497行）同样全部使用双花括号
- 统计确认：99处双花括号

#### 第2步：修复脚本
```bash
# 使用Python批量替换（sed无法处理嵌套花括号）
python3 << 'PYFIX'
content = content.replace('{{', '{')
content = content.replace('}}', '}')
# 结果: 99处 → 0处
```

#### 第3步：数据格式转换
发现 `news-data.json` 被重置为V1.1格式（19条扁平列表）：
```python
# 转换为V1.2按日期分组格式
v12_data = {
    "version": "1.2",
    "archive": {"2026-07-31": [19条新闻]},
    "dates": ["2026-07-31"],
    "stats": {...}
}
```

#### 第4步：重新生成HTML
使用**字符串拼接**替代f-string避免转义问题：
```python
html_parts = []
html_parts.append('''<style>''')  # 三引号原始字符串
html_parts.append('* { margin: 0; }')  # 单行普通字符串
html_parts.append('const NEWS_DATA = ' + json.dumps(data))  # 动态拼接
html_content = ''.join(html_parts)
```
