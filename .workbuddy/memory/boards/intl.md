- ⚠️ **「登记 ≠ 接入」三处同步原则（9-17 彭博教训）**：新增信源必须同时改 ①抓取清单（update-news.sh 注释 + 自动化 prompt + skill）②`AUTHORITY_ORDER`（否则 `index() else 99` 最低优先级，同题合并必被顶掉）③飞书「来源」select 选项（否则 800030005）—— 彭博曾仅在 config.json 登记 enabled=true 却三处皆缺，导致"看板长期查无此源"
- ⭐ **彭博正文取值法（9-17 回填实测）**：RSS `description` 仅 1 句，写不出"详尽中文摘要" → 走代理 `curl -x http://127.0.0.1:7890 'https://r.jina.ai/<彭博原文URL>'` **HTTP 200 / ~17KB**，含 `Published Time` + 正文**前 2–4 段**（付费墙截断）。提取：`Markdown Content:` 之后 → 剥 markdown 链接 → 按行取长度 ≥60 且非导航 → 前 2–4 段即 lede（例：华为 960DT 条拿到"Ascend 960DT 原定 2027 末商用→提前至 Q1，轮值董事长汪涛在上海年度峰会宣布"）。摘要事实**必须全部来自这几段**，禁外推
- ⭐ **单日回填 SOP（9-17 实践，65→72）**：`fetch_bloomberg_rss.py --days 3 --json` → 与现有版面标题逐条比对，**避开已被其他源覆盖的同题事件**（同题会被 `AUTHORITY_ORDER` 合并掉、白加）→ 选 5–7 条写全 schema（`collectedAt=今天`，`date` 用 URL 日期路径且 **≥ 昨天**，否则被 V2.11 移回旧版面）→ 追加 `data/news-webfetch.json` → `./update-news.sh --auto`（第3步整合 = 归今日版面；第4步 HTML；第5步飞书；第6步 push）。⚠️ **`.git/index.lock` 残留会让第6步 commit 静默失败**（`--auto` 到此退出，数据/HTML 已就绪）→ 判定法：`lsof` 为空 + mtime 落后 >2 分钟 → `rm -f .git/index.lock` 后手动 `git add data/news-data.json data/news-webfetch.json international-news.html gh-pages/international-news.html index.html gh-pages/index.html` + commit + push（push 若报 ref 更新失败，用 `git ls-remote origin main` 核实远端是否已含目标 commit）
