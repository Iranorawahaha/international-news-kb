# 国际新闻看板 - 项目记忆 (V1.0 正式版)

## 项目信息
- **项目名称**: 国际新闻看板 (International News Dashboard) ⭐V1.0
- **创建日期**: 2026-07-29
- **正式发布**: 2026-07-31
- **所属部门**: 华为公共及政府事务部
- **用途**: 高质量国际新闻自动采集、筛选、呈现和分享平台
- **访问地址**: https://iranorawahaha.github.io/international-news-kb/
- **定位**: 个人使用 + 向同事分享

## V1.0 核心功能
1. **双层采集引擎** - 基础中文信源(requests) + 英文权威信源(WebFetch API)
2. **URL完整性保障机制** ⭐ - 4道防线确保100%链接可点击跳转
3. **单文件自包含HTML** - CSS+JS+数据全部内嵌，无外部依赖（解决404问题）
4. **一键更新脚本** - `./update-news.sh` 自动化5步流程（3-5分钟）
5. **智能质量控制** - 自动去重、7大分类、重要性评分(高/中/低)、URL覆盖率检查
6. **GitHub Pages部署** - 全球CDN加速、HTTPS加密、免费托管、一键分享

## 技术架构 (V1.0优化后)
- **前端展示**: 单文件HTML (~32KB, 完全自包含)
- **后端采集**: Python 3.x + requests库 + WebFetch API
- **数据格式**: JSON (news-data.json)
- **版本控制**: Git + GitHub Pages
- **采集架构**: 双层（基础requests + WebFetch补充）

## 关键设计决策
1. **为什么选择单文件HTML?**
   - 初始多文件结构导致GitHub Pages部署后CSS/JS 404
   - 单文件架构消除路径依赖，部署简单，加载快速
   - 对于静态展示型页面是最佳选择

2. **为什么手动更新而非全自动?**
   - WebFetch步骤需在WorkBuddy环境中执行
   - 用户希望控制更新时机（每日2次: 9:30+17:00）
   - 确保数据质量，避免抓取低质量内容

3. **URL完整性保障机制的必要性?**
   - 2026-07-31发现11/26条新闻缺少URL（42%缺失率）
   - WebFetch API返回摘要而非结构化数据，容易遗漏URL字段
   - 4道防线从源头预防到最终质量把关全覆盖

## URL完整性保障机制 ⭐V1.0核心特性
**问题背景**: 2026-07-31发现11/26条新闻缺少原文链接

**解决方案: 4道防线**

| 防线 | 机制 | 位置 |
|------|------|------|
| 第1道 | WebFetch Prompt强制要求返回完整URL | fetch_news_v3.py 第85-114行 |
| 第2道 | validate_urls()自动验证覆盖率 | fetch_news_v3.py 新增方法 |
| 第3道 | HTML生成器渲染第9列"原文链接" | update-news.sh 第4步代码 |
| 第4道 | 质量标准要求URL覆盖率≥95% | DAILY-UPDATE-MANUAL.md 检查清单 |

## 关键经验教训 (已固化到文档)
1. **WebFetch采集时必须明确要求返回URL字段** - 否则容易遗漏
2. **数据整合前必须检查关键字段完整性** - 特别是url字段
3. **对缺失URL的信源应立即重试而非留空** - Google搜索备用方案不可靠
4. **静态网站优先选择单文件架构** - 避免路径依赖问题
5. **Git代理端口会动态变化** - 推送失败时检查$https_proxy环境变量
6. **定期清理工作空间** - 删除历史版本和临时文件保持清晰
