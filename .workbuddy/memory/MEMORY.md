## V1.2.2 核心改进 (2026-08-01 14:40更新)

### ✅ 中文信源质量革命性改进

**问题**: V1.2.1中文信源混杂大量软文/栏目/导航页（20条只有2条可用）
**根因**: 中文信源基础采集没有打分（默认0分）+ 没有智能过滤

**解决方案**:
1. **智能打分系统** (`_calculate_priority_score`):
   - 默认55分（不再是0）
   - 极高关键词（峰会/元首/制裁）→ 92分
   - 高优先级关键词（外交部/王毅/大使）→ 78分
   - 元首级触发词 → 95分
   - 过期事件强制 → 0分

2. **智能分类检测** (`_detect_category`):
   - 自动识别: 中美关系/外交资讯/经贸制裁/AI科技/地缘冲突/地区动态

3. **扩展黑名单至25+关键词**:
   - 导航: 海外分公司/专栏/系列账号/全球连线/记者手记/TOP NEWS
   - 营销: Business+/美容/Young minds/ancient wisdom
   - 索引: XI'S VISITS/SPECIAL REPORTS/热点专题

4. **新增5条过滤规则**:
   - 无URL的中文新闻 → 必为导航页（必过滤）
   - 0分内容 → 兜底过滤
   - 中国日报网英文标题 → 质量不足
   - 纯英文标题（中文信源）→ 不应出现
   - 软文营销 → 阈值1个就过滤

**效果**: 中文新闻从20条 → 2条（90%低质量过滤），保留高质量国际新闻

## 技术架构 (V1.2升级后)
- **前端展示**: 单文件HTML (~55KB, 完全自包含，V1.2增强日期Tab栏)
- **后端采集**: Python 3.x + requests库 + WebFetch API
- **数据格式**: JSON V1.2 (news-data.json, 按日期分组 {archive: {date: [...]}})
- **数据存档**: 飞书多维表格 Base (永久保存，增量追加，支持搜索筛选)
- **版本控制**: Git + GitHub Pages (根目录部署)
- **采集架构**: 双层（基础requests + WebFetch补充10信源）
- **数据保留**: 本地7天滚动窗口 + 飞书永久存档（双轨制）

## 关键设计决策
1. **为什么选择单文件HTML?**
   - 初始多文件结构导致GitHub Pages部署后CSS/JS 404
   - 单文件架构消除路径依赖，部署简单，加载快速
   - 对于静态展示型页面是最佳选择

2. **为什么手动更新而非全自动?**
   - WebFetch步骤需在WorkBuddy环境中执行
   - 用户希望控制更新时机（每日2次: 9:30+17:00）
   - 确保数据质量，避免抓取低质量内容

3. **URL完整性保障机制的必要性?**
   - 2026-07-31发现11/26条新闻缺少URL（42%缺失率）
   - WebFetch API返回摘要而非结构化数据，容易遗漏URL字段
   - 4道防线从源头预防到最终质量把关全覆盖

## 关键经验教训 (已固化到文档)
1. **WebFetch采集时必须明确要求返回URL字段** - 否则容易遗漏
2. **数据整合前必须检查关键字段完整性** - 特别是url字段
3. **对缺失URL的信源应立即重试而非留空** - Google搜索备用方案不可靠
4. **静态网站优先选择单文件架构** - 避免路径依赖问题
5. **Git代理端口会动态变化** - 推送失败时检查$https_proxy环境变量
6. **定期清理工作空间** - 删除历史版本和临时文件保持清晰
