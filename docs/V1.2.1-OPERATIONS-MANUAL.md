### Step 2: WebFetch补充（英文权威信源）

**操作位置**: WorkBuddy对话环境

**必选信源（4个）**:
1. 🔴 **路透社** (Reuters) - 全球财经政治
2. 🔴 **BBC News** - 英国视角国际新闻
3. 🔴 **南华早报** (SCMP) - 亚洲视角
4. 🔴 **卫报** (The Guardian) - 欧洲视角

**扩展信源（可选6个）**:
- CNN、NYT、半岛电视台、WaPo、AP、Politico

**要求格式**:
```json
{
  "title_en": "Original English Title",
  "title": "中文翻译标题",
  "summary": "2-3句摘要",
  "source": "路透社",
  "url": "https://...",
  "priority_score": 92,
  "is_summit_level": false,
  "category": "中美关系",
  "keywords": ["关键词1", "关键词2"]

```

**⚠️ 关键要求**:
- ✅ 必须包含完整URL（不能为空）
- ✅ 必须双语标题（title_en + title）
- ✅ priority_score必须≥75（否则会在Step 3被标记低质量）
- ✅ 元首级新闻必须标注 is_summit_level=true

**保存位置**: `data/news-webfetch.json` (手动或自动保存)

### Step 3: 数据整合（V1.2.1 - 核心质量控制）⭐

**这是最关键的一步！包含3道质量防线：**

#### 🛡️ 第1道防线：数据清洗

**过滤规则**:

| 规则 | 过滤条件 | 示例 |
|------|---------|------|
| 标题过短 | 中英文标题都<5字符 | "首页"、"导航" |
| 导航页面 | score=0 + 包含导航关键词 | "网站地图"、"联系我们" |
| 过期事件 | 包含历史事件关键词 | "APEC领导人非正式会议" |

**黑名单关键词**:
```python
NAVIGATION_KEYWORDS = [
    '导航', '首页', '网站地图', '联系我们', '关于我们',
    '版权声明', '隐私政策', '用户协议', '登录', '注册'
]

EXPIRED_EVENT_KEYWORDS = [
    'APEC领导人非正式会议',
    '对韩国进行国事访问',
    '对朝鲜进行国事访问',
    '出席博鳌亚洲论坛'
]
```

#### 🔄 第2道防线：智能去重

**唯一键设计**: `(title[:30], source)` 元组

**示例**:
```python
# 这两条会被识别为重复，只保留第一条
("Trump signs new trade executive order", "路透社")  # ✅ 保留
("Trump signs new trade executive order", "路透社")  # ❌ 删除

# 这两条不同来源，都会保留
("Trump signs new trade executive order", "路透社")  # ✅ 保留
("Trump signs new trade executive order", "BBC")      # ✅ 保留
```

#### 📊 第3道防线：重要性排序

**排序规则**（双层保障）:
1. **Python层（数据层）**: 存入JSON前排序
2. **JavaScript层（渲染层）**: 显示前再次排序

**排序算法**:
```python
def sort_key(article):
    summit = 1 if article.get('is_summit_level') else 0  # 元首级优先
    score = article.get('priority_score') or 0
    return (-summit, -score)  # 降序排列
```

**输出结果示例**:
```
⭐ [96] 习近平同拜登举行视频通话
🔴 [94] 美国宣布新的对华制裁措施
🟠 [88] 中美经贸磋商取得进展
🟡 [80] 欧盟讨论对华政策
🟢 [70] 地区性新闻...
```

**输入**: `data/news-basic.json` + `data/news-webfetch.json`
**输出**: `data/news-data.json` (V1.2格式，按日期分组)

**✅ 验证方法**:
```bash

python3 -c "
import json
d=json.load(open('data/news-data.json'))
total=sum(len(v) for v in d['archive'].values())
print(f'总计: {total}条 | 天数: {len(d[\"dates\"])}天')

# 检查去重效果（应该无重复）
```

## 4. 常见问题及解决方案

### ❌ 问题1: 页面空白/错乱

**症状**: GitHub Pages打开后白屏或CSS/JS错误

**原因**: HTML中包含双大括号 `{{` 或 `}}`

**解决方案**:
```bash
# 检查是否有双大括号
grep -r "{{{" *.html

# 如果有，重新运行 Step 4
# 或者手动替换
sed -i 's/{{{/[/g; s/}}}/]/g' *.html
```

**预防措施**:
- ✅ 使用字符串拼接而非嵌套f-string
- ✅ HTML生成后自动验证

---

### ❌ 问题2: 低重要性新闻排在顶部

**症状**: 首页显示的都是低分新闻，重要新闻被埋没

**原因**: 缺少排序逻辑（filterNews()未排序）

**解决方案**:
```bash
# 检查JavaScript是否包含排序函数
grep "sortArticlesByImportance" index.html

# 如果没有，重新运行 ./update-news.sh
# Step 3 和 Step 4 已内置排序逻辑
```

**预防措施**:
- ✅ Python层排序（数据层）
- ✅ JavaScript层排序（渲染层）
- ✅ 双层保障确保顺序正确

---

### ❌ 问题3: 飞书表出现重复数据

**症状**: 飞书表记录数 > 本地记录数

**原因**: 多次运行同步脚本时未去重

**解决方案**:
```bash
# 1. 查看当前状态
lark-cli base +record-list --base-token TOKEN --table-id ID --page-size 100 | wc -l

# 2. 手动清理重复（使用sync_to_feishu.py中的去重逻辑）
python3 scripts/sync_to_feishu.py --dedup-only

# 3. 验证清理结果
```

**预防措施**:
- ✅ sync_to_feishu.py V1.2.1 内置自动去重
- ✅ 同步前查询已有记录的唯一键
- ✅ 只插入不重复的新记录

---

### ❌ 问题4: 垃圾/导航/过期新闻混入

**症状**: 出现"首页导航"、"网站地图"、历史新闻等

**原因**: 采集阶段未过滤，或过滤规则不完善

**解决方案**:
```bash
# Step 3 的数据整合阶段会自动清洗
# 也可以单独运行清洗
python3 << 'CLEAN'
import json
# 加载并清洗数据（详见Step 3代码）
CLEAN
```

**预防措施**:
- ✅ fetch_news_v3.py 采集时就过滤（第1道防线）
- ✅ update-news.sh Step 3 再次清洗（第2道防线）
- ✅ 双层过滤确保零垃圾

---

### ❌ 问题5: Git推送失败

**症状**: `git push origin main` 报错

**原因**: 代理端口错误或网络问题

**解决方案**:
```bash
# 检查代理设置
echo $https_proxy
echo $http_proxy

# 如果端口不对，重新设置
export https_proxy=http://127.0.0.1:新端口号

# 重试推送
git push origin main
```

**预防措施**:
- ✅ 推送前自动检测代理设置
- ✅ 失败时提示检查代理

## 5. 故障排查清单

### 🚨 紧急故障处理流程

#### 场景A: 页面完全无法访问

```
1. 检查GitHub仓库是否正常
   → 访问 https://github.com/Iranorawahaha/international-news-kb

2. 检查GitHub Pages是否启用
   → Settings → Pages → Source: main branch

3. 检查index.html是否存在且有效
   → 应该 > 50KB，包含完整HTML

4. 强制刷新浏览器
   → Cmd+Shift+R (Mac) / Ctrl+Shift+R (Windows)
```

#### 场景B: 数据质量问题（重复/垃圾/排序错乱）

```
1. 立即停止更新，不要推送到GitHub

2. 检查本地数据
   → python3 -c "import json; d=json.load(open('data/news-data.json')); print(d)"

3. 手动清洗数据
   → 运行 Step 3 的清洗逻辑

4. 验证清洗结果
   → 检查总数量、去重率、排序

5. 重新生成HTML并本地预览
   → open index.html

6. 确认无误后再推送
   → git push origin main
```

#### 场景C: 飞书同步失败

```
1. 检查表格ID是否变更
   → lark-cli base +table-list --base-token TOKEN

2. 检查网络连接
   → ping open.feishu.cn

3. 查看详细错误日志
   → python3 scripts/sync_to_feishu.py --today -v

4. 手动重试（可跳过，不影响其他步骤）
```

## 7. 预防机制总结

### 已固化的防护措施（V1.2.1）

#### ✅ 防止页面错乱/崩溃
- **问题根因**: Python f-string嵌套产生 `{{ }}`
- **预防方案**:
  1. HTML生成使用字符串拼接（`.join()`）
  2. 生成后自动验证（grep `{{{` 必须返回0）
  3. 备份旧文件再覆盖

#### ✅ 防止重复数据累积
- **问题根因**: 飞书同步时未检查已有记录
- **预防方案**:
  1. 同步前查询飞书已有唯一键
  2. 基于 `(title[:30], source)` 去重
  3. 只插入新记录，不更新已有记录
  4. 采集阶段也做初步去重

#### ✅ 防止低质量信息混入
- **问题根因**: 采集阶段抓取到导航页/过期内容
- **预防方案**:
  1. **fetch_news_v3.py**: 采集时过滤（第1道防线）
  2. **update-news.sh Step 3**: 整合时再过滤（第2道防线）
  3. 黑名单关键词（导航/过期事件）
  4. 标题长度校验（<5字符过滤）
  5. 评分阈值（score=0 且含关键词才过滤）

#### ✅ 防止排序混乱
- **问题根因**: JavaScript渲染时未排序
- **预防方案**:
  1. **Python层**: 存入JSON前按重要性排序
  2. **JavaScript层**: 渲染前再次排序（双层保障）
  3. 排序算法: 元首级优先 → priority_score降序
  4. 每个日期分组内独立排序

#### ✅ 防止数据丢失
- **问题根因**: 覆盖写导致历史数据丢失
- **预防方案**:
  1. 本地采用7天滚动窗口（不立即删除）
  2. 飞书采用永久存档（从不删除）
  3. 双轨制确保数据安全
  4. Git版本控制保留所有历史
