## 1. 评分标准

每条新闻都有一个 `priority_score`（0-100 分），直接影响排序和展示。

### 1.1 五级重要性体系

| 级别 | 分数 | 标签 | 颜色 | 判定条件 |
|------|------|------|------|---------|
| ⭐ 元首级 | ≥95 | 元首级 | 橙 | `is_summit_level=true` 或 分数≥95 |
| 🔴 极高 | 90-94 | 极高 | 红 | 涉及重大冲突/制裁/峰会等 |
| 🟠 高 | 85-89 | 高 | 黄 | 重要地缘/外交/科技动态 |
| 🟡 中 | 75-84 | 中 | 蓝 | 有价值的国际新闻 |
| 🟢 低 | <75 | 低 | 灰 | 一般性报道 |

> ⚠️ `score == 0` 的内容会被**强制过滤**，不进入后续流程。

### 1.2 评分算法 (`_calculate_priority_score`)

| 分数档 | 触发关键词 | 示例 |
|--------|-----------|------|
| **95+** | 峰会、元首会晤、国事访问、视频通话 | "特朗普特使筹备习近平峰会" → 97 |
| **92+** | 制裁、反制、关税、导弹、战争、联合国、总统、习近平、特朗普 | "美国制裁43家中国企业" → 92 |
| **78+** | 外交部、王毅、布林肯、大使、南海、芯片、半导体、一带一路 | "中国海警台湾巡逻" → 78 |
| **55+** | 默认基础分（中文信源曾用过，现已弃用） | — |
| **0** | `priority_score := 0` | 未被评分或被标记为垃圾 |

### 1.3 元首级判定 (`is_summit_level`)

满足任一条件：
- 涉及中国国家元首（习近平）的外交活动
- 涉及美国总统（特朗普）的重大决策
- 中美元首直接会晤 / 通话 / 峰会
- 由 WebFetch 明确标注 `is_summit_level: true`

## 2. 数据清洗规则

### 2.1 采集阶段（`fetch_news_v3.py` — `save_data()`）

在保存数据前，按顺序执行以下检查。**命中任一条即移除**。

| # | 规则 | 条件 | 说明 |
|---|------|------|------|
| ① | **标题过短** | 中英文标题都 < 5 字符 | 防止空标题或无意义短标题 |
| ② | **零分内容** | `priority_score == 0` | 兜底过滤未被评分的条目 |
| ③ | **导航/栏目关键词** | 标题包含黑名单关键词（不限分数） | 见 §2.2 |
| ④ | **无URL中文信源** | 中文信源且缺失URL | 没有原文链接的导航/索引页 |
| ⑤ | **中国日报网质量不足** | 该来源且 score<70 或 无中文标题 | 英文软文标题严重 |
| ⑥ | **低质量中文** | 中国日报网/新华网且 score<50 | 分数阈值兜底 |
| ⑦ | **纯英文标题（中文信源）** | 来源为中文信源且仅含英文标题 | 翻译质量差 |
| ⑧ | **软文/营销** | 标题包含软文关键词 ≥1 个 | 见 §2.3 |

### 2.2 导航/栏目黑名单 (`NAVIGATION_KEYWORDS`)

以下关键词出现即判定为导航页/栏目索引，**不分分数一律过滤**：

```
通用导航: 导航, 首页, 网站地图, 联系我们, 关于我们, 版权声明, 隐私政策, 用户协议
栏目名称: 专栏, 系列账号, 记者手记, 全球连线, TOP NEWS, 要闻回顾, 一周回顾
索引页:   海外分公司, 热点专题, 出访专题, XI'S VISITS, SPECIAL REPORTS, 国际要闻
营销入口: Business+, 美容, 美妆, 降温神器, Young minds, ancient wisdom
```

### 2.3 软文/营销黑名单 (`SOFT_CONTENT_KEYWORDS`)

出现以下任一关键词即判定为软文（阈值：1 个）：

```
英文: Business+, A sun, sun that heals, Born by river, Time for a cool,
      cool change, beauty brands, surge in popularity

中文: 手记, 不亦, 乐乎, 金环, 城市看, 中俄地方, 枢纽通, 货值升, 激活,
      外贸动能, 乐在
```

### 2.4 整合阶段（`update-news.sh` — Step 3）

在合并新旧数据时，增加两道额外检查：

| # | 规则 | 说明 |
|---|------|------|
| ⑨ | **过期事件** | 标题包含已过期的历史事件关键词（见 §2.5） |
| ⑩ | **二次去重** | 基于 `(title[:30], source)` 在合并时去重 |

### 2.5 过期事件黑名单 (`EXPIRED_EVENT_KEYWORDS`)

这些词组指向历史新闻而非当日新闻，出现在标题中即过滤：

```
APEC领导人非正式会议, 对韩国进行国事访问, 对朝鲜进行国事访问,
出席博鳌亚洲论坛, 出席G20峰会, 出席金砖峰会
```

### 3.2 WebFetch 质量要求

WebFetch 返回的每条新闻**必须**包含：

- `title_en`: 英文原标题
- `title`: 中文翻译标题
- `summary`: 2-3 句中文摘要
- `url`: 完整的原文链接（`https://` 开头）
- `source`: 符合信源白名单
- `priority_score`: 0-100 分
- `is_summit_level`: true/false
- `category`: 6 大类之一
- `keywords`: 3-10 个关键词

## 4. 字段完整性检查

### 4.1 URL 覆盖率

- **目标**: ≥95% 的文章有有效 URL
- **当前**: 100%（英文 WebFetch 均含 URL）
- **不达标处理**: 无 URL 的中文文章直接过滤

### 4.2 标题规范

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 最小长度 | 中/英文标题至少一个 ≥5 字符 | 直接移除 |
| 含中文 | 至少包含中文标题或双语标题 | — |
| 禁止纯英文 | 中文信源不能仅有英文标题 | 直接移除 |

### 4.3 摘要要求

- 最少 10 字符（合理解释 2-3 句）
- WebFetch 返回的摘要一般 50-500 字符
- 无摘要时用标题填充（仅限特殊情况）

## 5. 去重规则

### 5.1 唯一键设计

```
唯一键 = (title[:30], source)
```

- **title[:30]**: 中文标题前 30 个字符
- **source**: 信源名称（如 "路透社"、"BBC"）
- 同一信源、标题前 30 字符相同的文章只保留一条

### 5.2 去重时机

| 阶段 | 执行位置 | 说明 |
|------|---------|------|
| **采集阶段** | `fetch_news_v3.py` — 基础采集 | 同一信源内去重 |
| **整合阶段** | `update-news.sh` — Step 3 | 新旧数据合并去重 |
| **飞书同步前** | `sync_to_feishu.py` | 查询飞书已有记录后再插入 |

### 5.3 飞书同步去重

同步前查询飞书表已有记录的唯一键，**只插入不存在的新记录**。当前查询实现存在 API 兼容性问题，需在后续版本修复。

## 6. 排序规则

### 6.1 双层排序保障

```
Layer 1 (Python / 数据层): sort_by_importance()
    → 存入 news-data.json 前排序

Layer 2 (JavaScript / 渲染层): sortArticlesByImportance()
    → 页面渲染前再次排序（每个日期分组内）
```

### 6.2 排序算法

```
优先级:
  1. is_summit_level == true → 排最前
  2. priority_score 降序排列

排序键: (-is_summit_level, -priority_score)
```

### 6.3 日期分组

- 页面显示按日期分组
- 每个日期分组内独立排序
- 日期间按自然倒序排列（最新日期最前）

## 7. 规则执行顺序

在完整更新流程（`./update-news.sh`）中，规则的**执行顺序**如下：

```
┌──────────────────────────────────────────────────────┐
│  Step 1: 基础采集 (V1.2.3 已跳过中文)               │
│    → 无数据产出                                      │
├──────────────────────────────────────────────────────┤
│  Step 2: WebFetch 补充                               │
│    ✅ 信源白名单检查 (仅限11个英文信源)               │
│    ✅ 字段完整性检查 (url/title/summary 不可缺)       │
├──────────────────────────────────────────────────────┤
│  Step 3: 数据整合 ← 质量控制中心                     │
│    ① 标题过短过滤                                     │
│    ② 零分内容过滤                                     │
│    ③ 导航/栏目黑名单过滤                              │
│    ④ 过期事件过滤                                     │
│    ⑤ 去重 (唯一键)                                    │
│    ⑥ 按重要性排序 (⬇ priority_score)                  │
├──────────────────────────────────────────────────────┤
│  Step 5: 飞书同步                                    │
│    ✅ 同步前查询已有记录去重                          │
└──────────────────────────────────────────────────────┘
```
